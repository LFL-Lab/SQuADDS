squadds.ml.capacitance.benchmark module#

Scoring of capacitance models with the paper’s metric rules.

Per layout and entry kind: the median over its entries of |p - y| / max(|y|, 0.1 fF) in %, the MAE and the RMSE in fF; then the mean over layouts (the layout mean), so a 68-conductor chip and a two-pad capacitor count once each. Kinds: mutual (every off-diagonal pair, the headline), signal-signal, signal-ground, signal_self, ground_self. Unknown (NaN) label entries are dropped and counted. Every report carries the wall time, machine and thread count.

Validation scoring is open to everyone. Test scoring (split="test") is maintainer-only: once per declared model, recorded in a ledger, and only for models whose training keys are disjoint from the scored layouts (models trained on the TRAIN split).

squadds.ml.capacitance.bridge module#

Bridges from the planar capacitance models into the existing SQuADDS workflows.

  • MLSimulator: the call and result shape of the capacitance (Q3D / LOM) path of AnsysSimulator (simulate(device_dict) -> {"design", "sim_options", "sim_results"}) plus fidelity="ml:<model>" and timing. Input: a Qiskit Metal design or component, a SQuADDS row (rebuilt with the component registry) or a GDS path.

  • predict_dataframe: predictions for the rows of an Analyzer result (Analyzer.predict_capacitance calls it).

  • transmon_cross_capacitances / EC_MHz / g_MHz / EC_MHz_from_matrix: feed squadds.calcs.

Export (export=): "auto" (default) writes a component of a dataset family (squadds.layouts.dataset_export: interdigital / paddle, concentric, star, Xmon, TransmonPocket, shielded concentric) exactly as the dataset was exported, so the model sees the input it was trained on; any other layout (e.g. quantum-metal TransmonCross, several components) goes through export_qgeometry_gds (square ground domain, 169 um padding). "dataset" / "qgeometry" force one. The result records it in export. Star rows of the SQuADDS view carry their style in notes.export_style. Conductor bodies are named from the qgeometry they overlap (planar_capacitance_view.QGEOMETRY_NETS), so the sim_results keys match the SQuADDS configs (north_to_south, cross_to_claw, …).

Contributing planar capacitance data and models to SQuADDS/SQuADDS_PlanarCapacitance (Hugging Face pull requests).

Data: a contribution directory in the template layout (squadds/database/templates/planar_capacitance_contribution):

validate_capacitance_contribution(dir) runs the dataset validator (schema, GDS readback, net names, label QC, duplicates, stack, licence, privacy) and contribute_capacitance(dir) opens a pull request adding contrib/<org>-<batch>/ and its validation_report.md. Test-set scores are never self-reported: they are run by the maintainers, once per declared model, only for models trained on the TRAIN split.

squadds.ml.capacitance.predictor module#

GDS -> full N x N Maxwell capacitance matrix with a released model.

The steps are those of the tl-squadds Spaces (geomgnn.paper.predict / geomgnn.flagship.predict), statement for statement: scene from the prepared layout -> geometric embedding (the model’s far-sample setting) -> thin-film priors under the model’s prior stack (or the learned prior surrogate) -> networks. The embedding and the priors are cached in memory by the layout’s geometry hash, so a repeated layout skips them.
